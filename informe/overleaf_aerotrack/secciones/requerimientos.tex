\subsection{Fichas Detalladas de Casos de Uso}
\label{subsec:casos-uso-detalle}

Cada ficha incluye el diagrama de caso de uso del informe original. Los 11 diagramas no
se pudieron extraer del PDF fuente; el recuadro marcado \texttt{imagenes/cu-XX.png} debe
reemplazarse por la figura correspondiente.

\subsubsection{CU-01: Configurar el Plano y las Cámaras}
\textbf{Actor Principal:} Operador.

\textbf{Precondiciones:} El servidor local está en ejecución.

\textbf{Flujo Principal:}
\begin{enumerate}
  \item El operador crea un plano en blanco o importa una imagen, PDF o DXF.
  \item Si la fuente es una imagen o un PDF, el operador recorta la región útil; el sistema la
  reduce a un dibujo esquemático de líneas mediante detección de bordes, en vez de
  conservar la fotografía completa.
  \item El operador coloca cada cámara sobre el plano y define su alcance orientativo.
  \item El operador declara qué cámaras son vecinas entre sí.
\end{enumerate}

\textbf{Postcondiciones:} El plano queda registrado con sus cámaras y disponible para la
calibración (CU-02).

\figuraPendiente{cu-01.png}{11cm}{4.5cm}{Diagrama de caso de uso CU-01: Configurar el
Plano y las Cámaras.}{fig:cu01}

\subsubsection{CU-02: Calibrar una Cámara}
\textbf{Actor Principal:} Operador.

\textbf{Precondiciones:} Existe una fuente de video válida asociada a la cámara.

\textbf{Flujo Principal:}
\begin{enumerate}
  \item El operador marca un punto de referencia del suelo en el video y su correspondencia
  exacta en el plano.
  \item El operador repite la marcación un mínimo de cuatro veces (6 a 8 correspondencias
  recomendadas, repartidas por toda el área de interés).
  \item El sistema calcula la homografía píxel a plano a partir de esas correspondencias.
\end{enumerate}

\textbf{Postcondiciones:} La cámara queda calibrada y habilitada para proyectar posiciones
al plano compartido.

\textbf{Excepción:} el sistema rechaza la calibración si las correspondencias resultan
geométricamente inconsistentes.

\figuraPendiente{cu-02.png}{11cm}{4.5cm}{Diagrama de caso de uso CU-02: Calibrar una
Cámara.}{fig:cu02}

\subsubsection{CU-03: Procesar una Fuente y Hacer Seguimiento}
\textbf{Actor Principal:} Operador.

\textbf{Precondiciones:} La cámara está calibrada o en modo de prueba (CU-11).

\textbf{Flujo Principal:}
\begin{enumerate}
  \item El operador elige un detector: HOG de referencia, P2PNet, o YOLO con pesos locales
  propios.
  \item El operador inicia la sesión de procesamiento.
  \item El sistema detecta personas en cada cuadro de video.
  \item El sistema asigna a cada persona un identificador local estable dentro de esa cámara,
  mediante seguimiento por distancia euclidiana y asignación húngara en dos etapas.
\end{enumerate}

\textbf{Postcondiciones:} Las personas quedan detectadas y seguidas de forma continua
dentro de la cámara, cada una con su identificador local.

\textbf{Excepción:} si el detector elegido es P2PNet, la posición no se proyecta al plano,
porque ese modelo localiza cabezas y no pies; ese modo sirve solo para validar detección y
seguimiento por cámara.

\figuraPendiente{cu-03.png}{11cm}{5.5cm}{Diagrama de caso de uso CU-03: Procesar una
Fuente y Hacer Seguimiento.}{fig:cu03}

\subsubsection{CU-04: Detectar y Alertar Aglomeraciones (Regla Global)}
\textbf{Actor Principal:} Operador.

\textbf{Precondiciones:} Hay una sesión en ejecución.

\textbf{Flujo Principal:}
\begin{enumerate}
  \item El operador define un radio de agrupamiento, una cantidad mínima de personas y un
  tiempo de permanencia, de forma global o por zona.
  \item El sistema evalúa de forma continua si una concentración de personas cumple los tres
  criterios de forma sostenida.
  \item El sistema marca una alerta cuando se cumple esa condición.
\end{enumerate}

\textbf{Postcondiciones:} La alerta queda registrada y disponible para su visualización
(CU-06) y su exportación (CU-07).

\figuraPendiente{cu-04.png}{11cm}{5cm}{Diagrama de caso de uso CU-04: Detectar y
Alertar Aglomeraciones (Regla Global).}{fig:cu04}

\subsubsection{CU-05: Visualizar el Plano en Vivo y el Video por Cámara}
\textbf{Actor Principal:} Operador.

\textbf{Precondiciones:} Existe una sesión activa o una imagen retenida disponible.

\textbf{Flujo Principal:}
\begin{enumerate}
  \item El operador observa el plano compartido, con los nodos activos, sus trayectorias
  recientes y las aglomeraciones resaltadas.
  \item El operador alterna a la vista de video real de una cámara específica.
  \item El sistema superpone sobre ese video las cajas de detección y el identificador de cada
  persona.
\end{enumerate}

\textbf{Postcondiciones:} El operador cuenta con visibilidad operativa en tiempo real del
estado del terminal, con ambas vistas disponibles en todo momento.

\figuraPendiente{cu-05.png}{11cm}{5cm}{Diagrama de caso de uso CU-05: Visualizar el
Plano en Vivo y el Video por Cámara.}{fig:cu05}

\subsubsection{CU-06: Exportar Reportes}
\textbf{Actor Principal:} Operador.

\textbf{Precondiciones:} La sesión activa tiene datos observados.

\textbf{Flujo Principal:}
\begin{enumerate}
  \item El operador selecciona el tipo de reporte: zonas calientes, flujo horario, ocupación,
  trayectorias o comparativas.
  \item El operador selecciona el formato de salida.
  \item El sistema genera el archivo en PDF, Excel, CSV o JSON.
  \item El sistema señala explícitamente si el origen de los datos es una fuente real o la
  demostración sintética.
\end{enumerate}

\textbf{Postcondiciones:} El sistema entrega un archivo exportado con la ocupación por
zona, la evolución temporal y las trayectorias de la sesión, con su origen declarado.

\figuraPendiente{cu-06.png}{11cm}{5cm}{Diagrama de caso de uso CU-06: Exportar
Reportes.}{fig:cu06}

\subsubsection{CU-07: Gestionar Zonas de Interés (ROI)}
\textbf{Actor Principal:} Operador.

\textbf{Precondiciones:} El plano está configurado (CU-01).

\textbf{Flujo Principal:}
\begin{enumerate}
  \item El operador dibuja polígonos, rectángulos o círculos sobre el plano.
  \item El operador clasifica cada área (ROI, comercio, cola, restringida, sala, pasillo, muro,
  puerta).
  \item El sistema puede sugerir automáticamente sectores según la ocupación observada.
  \item El operador acepta, ajusta o descarta cada sugerencia.
\end{enumerate}

\textbf{Postcondiciones:} Las zonas quedan registradas y disponibles para las reglas de
aglomeración (CU-09) y los reportes por zona (CU-07).

\figuraPendiente{cu-07.png}{11cm}{5cm}{Diagrama de caso de uso CU-07: Gestionar Zonas
de Interés (ROI).}{fig:cu07}

\subsubsection{CU-08: Configurar Reglas de Aglomeración por Zona}
\textbf{Actor Principal:} Operador.

\textbf{Precondiciones:} Existe al menos una zona dibujada (CU-08).

\textbf{Flujo Principal:}
\begin{enumerate}
  \item El operador selecciona una zona registrada.
  \item El operador define para esa zona una cantidad mínima de personas y un tiempo de
  permanencia propios, independientes de la regla global.
  \item El sistema activa la regla y la evalúa de forma continua sobre esa zona.
\end{enumerate}

\textbf{Postcondiciones:} La zona queda con una regla de aglomeración propia, y el sistema
emite alertas específicas ajustadas a su uso (por ejemplo, una cola frente a una sala de
espera).

\figuraPendiente{cu-08.png}{11cm}{5cm}{Diagrama de caso de uso CU-08: Configurar
Reglas de Aglomeración por Zona.}{fig:cu08}

\subsubsection{CU-09: Consultar el Dashboard Ejecutivo}
\textbf{Actor Principal:} Administrador.

\textbf{Precondiciones:} La sesión tiene datos observados.

\textbf{Flujo Principal:}
\begin{enumerate}
  \item El usuario abre el dashboard ejecutivo.
  \item El sistema muestra el ranking de zonas por ocupación acumulada.
  \item El sistema muestra la evolución de personas observadas en el tiempo.
  \item El sistema sugiere zonas a evaluar comercialmente según el tránsito medido.
\end{enumerate}

\textbf{Postcondiciones:} El usuario obtiene información de negocio derivada del tránsito
medido, sin identificación individual de las personas observadas.

\figuraPendiente{cu-09.png}{11cm}{5cm}{Diagrama de caso de uso CU-09: Consultar el
Dashboard Ejecutivo.}{fig:cu09}

\subsubsection{CU-10: Validar una Fuente en Modo Laboratorio}
\textbf{Actor Principal:} Operador.

\textbf{Precondiciones:} La cámara fue agregada al proyecto.

\textbf{Flujo Principal:}
\begin{enumerate}
  \item El operador selecciona la cámara a validar de forma aislada, antes de integrarla a la
  operación real.
  \item El sistema prueba la señal y la resolución de la fuente.
  \item El sistema mide el tiempo de procesamiento.
  \item El sistema evalúa la calidad de la calibración y la estabilidad del seguimiento.
\end{enumerate}

\textbf{Postcondiciones:} La cámara queda validada o rechazada, con un registro de las
métricas medidas, antes de sumarse a una sesión real.

\figuraPendiente{cu-10.png}{11cm}{5.5cm}{Diagrama de caso de uso CU-10: Validar una
Fuente en Modo Laboratorio.}{fig:cu10}

\subsubsection{CU-11: Consultar la Auditoría del Sistema}
\textbf{Actor Principal:} Auditor.

\textbf{Precondiciones:} Existe al menos una acción registrada (guardar, iniciar, pausar o
detener).

\textbf{Flujo Principal:}
\begin{enumerate}
  \item El usuario abre el registro de auditoría.
  \item El sistema muestra las acciones del operador durante la ejecución del servidor, con
  fecha, hora y detalle.
\end{enumerate}

\textbf{Postcondiciones:} Queda disponible la trazabilidad operativa completa de la
sesión, sin que el registro contenga identidades reales de las personas observadas.

\figuraPendiente{cu-11.png}{11cm}{4cm}{Diagrama de caso de uso CU-11: Consultar la
Auditoría del Sistema.}{fig:cu11}
